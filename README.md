# Enterprise Private GPT

## Запуск через Docker Compose

Потребуются Docker с Compose v2 и браузер. При первой подготовке интернет нужен для
образов, Python-зависимостей и весов моделей. E5 входит в общий образ `app` и `ingest`.
Qwen загружается в отдельный том Docker. На Docker Desktop для macOS Ollama
выполняет генерацию на CPU.

```sh
docker compose build app
docker compose up -d --wait qdrant ollama
docker run --rm --entrypoint sh \
  -v enterprise-private-gpt_ollama_models:/root/.ollama \
  ollama/ollama:0.13.5 -ec '
    ollama serve &
    server=$!
    trap "kill $server" EXIT
    for attempt in $(seq 1 30); do
      if ollama list >/dev/null 2>&1; then ollama pull qwen3:4b; exit; fi
      sleep 1
    done
    exit 1
  '
docker compose up -d
```

Откройте локальный чат по адресу `http://127.0.0.1:7860`. Выберите **«Только EN»**
для английских документов, **«EN+RU»** для обоих наборов или **«Только RU»**
для русских документов. Дождитесь статуса «Индекс готов» перед проверкой нового
корпуса. Режим можно сменить прямо в чате.

При повторном запуске достаточно `docker compose up -d --no-build --pull never`.
Сервисы общаются по внутренней сети Docker. У `app` есть отдельная сеть для
браузера. При старте контейнер удаляет маршрут по умолчанию и запускает Gradio
от непривилегированного пользователя. На хост опубликован только порт чата,
привязанный к `127.0.0.1`. Индекс и модель сохраняются в именованных томах.

## Сервисы

| Сервис | Назначение |
|---|---|
| `app` | Gradio, кнопки управления корпусом, поиск, генерация и вывод источников. |
| `ingest` | Принимает задания от приложения, обрабатывает документы и пересобирает индекс. |
| `qdrant` | Хранит чанки, метаданные и эмбеддинги. Ищет по активной коллекции `knowledge_active`. |
| `ollama` | Запускает локальную модель `qwen3:4b`. |

При пересборке `ingest` проверяет новую коллекцию, переключает на неё алиас
`knowledge_active` и удаляет предыдущую коллекцию. Пока новая версия готовится,
чат использует текущую коллекцию.

## Как работает обработка вопроса

**Чат → текст вопроса → E5 → один вектор вопроса → поиск в Qdrant → тексты найденных чанков → промпт для Qwen 3 → ответ в чат.**

1. **После нажатия кнопки в чате** `ingest.py` читает выбранные документы, разбивает текст на чанки и строит по одному вектору на чанк с помощью `multilingual-e5-small` (E5). Затем записывает чанки в Qdrant.
2. Когда пользователь задаёт вопрос в чате, `rag.py` преобразует его текст в один вектор с помощью той же E5 и передаёт его в Qdrant для поиска.
3. **Qdrant возвращает Top-K найденных чанков.** Для каждого результата приложение получает ID, оценку близости и сохранённые данные — текст чанка, имя файла и страницу или раздел.
4. `rag.py` берёт **исходный вопрос и тексты найденных чанков**, добавляет инструкцию отвечать по этому контексту и отправляет промпт в Ollama. Qwen 3 получает текст. Вектор вопроса используется на этапе поиска.
5. Приложение показывает ответ в чате вместе с источниками по сохранённым метаданным.

### Как Top-K влияет на поиск и источники

В браузере доступны значения **Top-K = 1, 3 и 5**. Рассмотрим, как формируется ответ при `Top-K = 3`.

1. **Qdrant ранжирует чанки.** Он сравнивает вектор вопроса с векторами активного корпуса по косинусной близости и возвращает до трёх ближайших чанков в порядке убывания оценки.
2. **`rag.py` передаёт Qwen 3 тексты найденных чанков** вместе с вопросом. Каждый фрагмент получает номер по позиции в выдаче, например `[1]`, `[2]`, `[3]`.
3. **Qwen 3 указывает номера фрагментов, на которые опирается ответ.** Если модель указала `[2]`, чат покажет только второй фрагмент. Если указала `[1, 2]`, покажет оба. Блок «Использованные фрагменты» выводит источники ответа.

При проверке на корпусе EN вопроса «Сколько раз за ночь отключался инвертор INV-11 при ошибке E-201?» чанк письма `EDT-0000556.eml` с фразой про девять отключений оказался на втором месте в выдаче Qdrant. При `Top-K = 3` этот чанк попал в контекст. Qwen 3 сослалась на него, и в интерфейсе появился один источник.

## Результаты тестирования

### Ложный отказ на корпусе EN + RU

На корпусе из 10 документов при `Top-K = 3` задали вопрос «Сколько раз за ночь отключался инвертор INV‑11 при ошибке E‑201?». В письме `EDT-0000556.eml` указано, что инвертор отключался **девять раз**. Чат ответил: «В загруженных документах нет ответа на этот вопрос.»

Чтобы выяснить причину, повторили поиск того же вопроса напрямую в Qdrant и проверили все три чанка.

| Место | Корпус | Файл | Косинусная близость | Есть факт о девяти отключениях |
|---:|---|---|---:|---|
| 1 | EN | `EDT-0000556.eml` — письмо об ошибке E-201 | 0.8097 | Нет |
| 2 | RU | `0000939_BER-201700850.docx` — отчёт о станциях быстрой зарядки | 0.8060 | Нет |
| 3 | RU | `0008196_EVE-2026-0466.xlsx` — бюджет сертификации техников | 0.8045 | Нет |

Qdrant нашёл чанк из нужного письма, а фраза про девять отключений находится в другом чанке, который оказался за пределами Top-3. По полученному контексту отказ Qwen 3 корректен. Для RAG в целом это ошибка поиска, поскольку нужный факт был в базе, но до модели не дошёл.

### Повторная проверка с Top-K = 5 на корпусе EN + RU

В браузере повторили тот же вопрос «Сколько раз за ночь отключался инвертор INV‑11 при ошибке E‑201?» по тем же 10 документам. При `Top-K = 5` чат ответил **«9.»** и показал чанк из [`EDT-0000556.eml`](data/demo/en/EDT-0000556.eml) с оценкой косинусной близости `0.803`.

> The unit tripped nine times overnight, though the fault clears itself after a manual restart.

| Top-K | Результат поиска | Ответ в чате |
|---:|---|---|
| 3 | Чанк с числом отключений остался за пределами выдачи. | «В загруженных документах нет ответа на этот вопрос.» |
| 5 | Чанк с числом отключений попал в контекст и был указан как источник. | «9.» |

В этом тесте увеличение `Top-K` с 3 до 5 позволило найти нужный англоязычный фрагмент по вопросу на русском и дать подтверждённый ответ на объединённом корпусе.

### Ложный отказ при наличии ответа в контексте по циркуляру MEM‑00565

Для того же вопроса на корпусе EN + RU проверили выдачу Qdrant при `Top-K = 5`.

| Место | Файл | Косинусная близость | Есть дата комплаенс-аудита |
|---:|---|---:|---|
| 1 | `0003296_MEM-00565.txt` | 0.8317 | Да, 12 ноября |
| 2 | `0003296_MEM-00565.txt` | 0.8290 | Нет |
| 3 | `0008196_EVE-2026-0466.xlsx` | 0.8196 | Нет |
| 4 | `0008196_EVE-2026-0466.xlsx` | 0.8190 | Нет |
| 5 | `0008196_EVE-2026-0466.xlsx` | 0.8164 | Нет |

В повторном прогоне Qdrant вернул одни и те же первые три чанка при обоих значениях `Top-K`. Чанк с датой **«12 ноября»** был первым в обоих промптах. Ollama вернула разные ответы:

| Top-K | Токенов в промпте | Ответ модели до обработки приложением |
|---:|---:|---|
| 3 | 1 158 | `{"answer": "12 ноября", "sources": [1]}` |
| 5 | 2 080 | `{"answer": "", "sources": []}` |

Оба промпта уложились в лимит контекста в 4 096 токенов. При `Top-K = 5` модель получила правильный фрагмент и вернула пустой ответ и список источников. Приложение отобразило это как отказ. Возможная причина — два дополнительных чанка из таблицы бюджета. Они были близки к вопросу по оценке Qdrant, увеличили промпт и могли отвлечь Qwen 3 от строки с датой аудита.

#### Возможный обход со ступенчатым повышением Top-K

1. Начать с `Top-K = 3`. Если модель дала ответ с источником, завершить запрос.
2. При отказе повторить тот же вопрос по тому же корпусу с `Top-K = 5`.
3. Показать ответ с источником, если он найден. Если модель снова отказалась, вернуть обычное сообщение об отсутствии ответа в загруженных документах.

В тесте по циркуляру хватило бы первого шага. В тесте про инвертор повторный поиск с пятью чанками нашёл фрагмент, которого не было в Top-3. Повторный прогон увеличивает задержку запросов, на которые модель сначала отказалась отвечать.

### Сравнение Qwen 3 и RAG на вопросе о рабочей неделе

Один и тот же вопрос «Сколько рабочих дней в стандартной рабочей неделе?» задали напрямую модели в контейнере Ollama и через браузерный чат.

| Режим | Контекст | Ответ | Время |
|---|---|---|---|
| Qwen 3 `qwen3:4b` напрямую | Без документов | «5 рабочих дней.» | Около 3 мин 28 с по журналу Ollama |
| Браузерный RAG | Корпус RU, `Top-K = 3` | «В загруженных документах нет ответа на этот вопрос.» | Поиск 0,11 с, генерация 66,42 с, всего 66,52 с |

Замеры RAG взяты из блока «Время обработки» в браузере. Длительность прямого запроса соответствует записи `/api/generate`, сопоставленной по порядку событий в журнале Ollama. Журнал фиксирует длительность HTTP-запроса без текста вопроса.

В этих прогонах браузерный RAG завершился примерно в 3,1 раза быстрее. В обоих режимах основное время заняла работа модели. Прямой запуск вывел длинное рассуждение и итоговый ответ. В RAG модель вернула короткий результат, который приложение показало как отказ.

Прямой запрос к модели выполняется из каталога проекта.

```sh
docker compose exec -T ollama ollama run --think=false qwen3:4b "Сколько рабочих дней в стандартной рабочей неделе?" </dev/null
```

Это контрольный тест на вопрос вне базы. В исходном корпусе RU было пять документов без правила о продолжительности стандартной рабочей недели. Повторная индексация этих же файлов дала корректные отказы при `Top-K = 3` и `Top-K = 5`.

В двух ручных прогонах того же вопроса на исходном корпусе RU получили следующие замеры.

| Top-K | Поиск, с | Генерация, с | Всего, с | Ответ |
|---:|---:|---:|---:|---|
| 3 | 0,12 | 9,89 | 10,01 | Отказ |
| 5 | 0,11 | 83,04 | 83,15 | Отказ |

Эти времена относятся к двум отдельным прогонам. Порядок запуска и прогрев модели в этом сравнении не контролировались. Поиск занял около 0,1 с в обоих случаях, а основная разница пришлась на генерацию.

## Итоги задания

Локальный чат поддерживает три режима корпуса: EN, RU и EN + RU. Все четыре сервиса запускаются через Docker Compose.

### Почему выбрали этот стек

| Технология | Почему выбрали |
|---|---|
| **`multilingual-e5-small` и Sentence Transformers** | Компактная модель строит локально 384-мерные векторы вопросов и чанков. Общее пространство для русского и английского позволило находить английские источники по русским вопросам без отдельного перевода. |
| **Qdrant** | Хранит векторы вместе с текстом чанка и метаданными источника, выполняет поиск по косинусной близости. Алиас коллекции позволяет переключить чат на новый индекс после успешной пересборки корпуса. |
| **Qwen 3 `qwen3:4b` и Ollama** | Модель помещается в память тестового стенда и работает на CPU. Ollama предоставляет локальный API, через который приложение передаёт вопрос и найденные фрагменты и получает ответ с номерами источников. |
| **Python и LangChain Text Splitters** | Python связывает извлечение текста, векторизацию, поиск и генерацию. `RecursiveCharacterTextSplitter` позволяет настроить размер и перекрытие чанков, чтобы часть контекста сохранялась на границах фрагментов. |
| **FastAPI и Gradio** | FastAPI принимает команды индексации от приложения. Gradio даёт браузерный интерфейс для смены корпуса, выбора Top-K, просмотра источников и времени обработки. |
| **Docker Compose** | Воспроизводит запуск четырёх сервисов, задаёт их сетевые связи и сохраняет индекс Qdrant и веса Ollama в отдельных томах между перезапусками. |
